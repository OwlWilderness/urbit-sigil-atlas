# Security

No stable release or supported-version policy has been established. Use only a corrected and explicitly accepted native package; this predecessor has a known preference durability defect.

Do not put credentials, ship login codes, pier contents, cookies, private keys, authenticated URLs or personal deployment details in issues, logs or screenshots. The app should use the installing ship's existing Eyre session and Gall same-ship checks, never an external login service or relaxed access control.

For a suspected vulnerability, use the repository's private vulnerability reporting feature **if the eventual owner has enabled it**. No reporting email or guaranteed private reporting service has been established. If none is available, ask the maintainer for a private contact without posting exploit steps, credentials or sensitive attachments publicly. Do not test other people's ships. Include a sanitized affected revision, impact and minimal reproduction through the agreed private channel.

The export scanner is a bounded engineering aid, not a comprehensive secret detector or security audit. Owner review remains required before publication, including outgoing Git history and third-party distribution terms.

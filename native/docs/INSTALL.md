This is current layout3 source for the native 0.1.1 application, not a remote consumer installer. ## Metadata and target gates

The public source contains `native/desk/desk.docket-0.example`, with deliberately invalid `PUBLISHER_SHIP` and pre-glob `0v0`. It is not directly installable. Supply a verified source ship and separately review metadata in a staging copy; do not infer distribution authority from authorship labels or a planned website. Runtime metadata is target-bound and deliberately excluded. Existing installed metadata must be retained; owner-reported delivery is distinct from independent served-byte verification. A local successful build alone is not native compile/install proof or authorization.

Before first installation, the owner/operator must confirm the intended ship, `%zuse 408`, Clay desk absence, actual Gall agent absence and a permitted file-staging path. A missing tile/desk is not proof of Gall absence. Back up exact target files/state and stop on collisions or inconclusive checks.

## Existing installation / frontend-only layout3 update

Back up actual installed source/state and Docket glob/source. Retain newer installed metadata; do not overwrite an actual glob with a pre-glob descriptor. This layout3 successor changes no Hoon source, so do not reinstall/restart Hoon solely for the presentation update. Any future frontend update requires a complete glob; the owner already reports the current glob delivered, so do not repeat it for repository synchronization. Native-source updates require separate admission, same-desk commit and migration verification. Never wipe a production ship to manufacture persistence evidence.
